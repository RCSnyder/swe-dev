# SWE Dev Theoretical Minimum Finder

Run a bounded research investigation over `$ARGUMENTS` and emit exactly one durable artifact.

The purpose is not to produce an impressive survey or maximal reading list. It is to identify the smallest adequate foundation for a defined target capability, show why each unit survives removal, and create tests that reveal whether a learner can regenerate and defend it.

Use the Landau-inspired principles of minimum, ownership, process, productive struggle, and defense as workflow requirements. Do not repeat unverified historical claims from that inspiration or reproduce humiliation as pedagogy.

## Hard contract

1. **One command in, one artifact out.**
   - Do not create scratch notes, source caches, side reports, bibliographies, or intermediate project files.
   - Browse, inspect, calculate, and reason in working context only.
   - Write exactly one Markdown file at the end.
2. **The model is never a source.** AI synthesis is Tier 5: hypothesis or connective tissue only.
3. **No invented provenance.** Never invent a URL, DOI, page number, quotation, author, date, edition, standard number, citation count, canonical status, consensus claim, or research trend.
4. **No citation laundering.** A search-result snippet or secondary source that points at an original is not a substitute for inspecting the original when the original is load-bearing and reachable.
5. **No fake verification.** “Verified” means the source was actually opened/read in this run to the extent needed for the claim. A reachable URL is not the same as verified content.
6. **No forced symmetry or size.** Do not manufacture "both sides," a fixed number of units, controversy, or weakness when the field does not support it.
7. **No source, no load-bearing fact.** If a material claim cannot be grounded, label it `[UNKNOWN]`, `[INFERENCE]`, or `[SYNTHESIS]` and do not let it carry a major conclusion.
8. **Stop rather than bluff.** If browsing, source access, or file writing is unavailable, say so inside the single artifact and lower its status. Never simulate research.
9. **Minimum means deletable.** Retain no unit unless removing it causes a specific failure in the target capability, prerequisite closure, or transfer across representative problems.
10. **Answers are not mastery.** Every examination must expose the learner's assumptions, route, checks, recovery, and boundary awareness, not only final answers.

Read [source-discipline.md](./references/source-discipline.md) before research. Read [domain-adapters.md](./references/domain-adapters.md) if the topic is not straightforward software/computer science. Read [artifact-contract.md](./references/artifact-contract.md) before writing the final file.

## Input contract

Interpret `$ARGUMENTS` as the user's research target. It may be:
- a field: `control theory`
- a target capability: `evaluate production distributed-database designs`
- a question: `what is the theoretical minimum for computational neuroscience?`
- an existing curriculum to cut: `audit this machine-learning reading plan for prerequisite gaps and excess`
- an applied problem: `understand grid-scale battery degradation well enough to compare architectures`

If an explicit `--out <path>` is present, use it. Otherwise write:

`theoretical-minimums/<topic-slug>.md`

Create the `theoretical-minimums/` directory if needed. This directory is not a second artifact.

If that path already exists and its frontmatter contains `generator: swe-dev-theoretical-minimum-finder`, refresh that same artifact rather than multiplying files. If it exists but is not generated by this skill, choose `theoretical-minimums/<topic-slug>-minimum.md` and do not overwrite unrelated work.

Do not ask routine clarification questions. Infer a reasonable target capability, entry assumptions, and scope, then record them under **Target capability and scope**. Ask only when ambiguity would make the proposed minimum materially unsafe or meaningless.

## Research loop

Use the smallest loop that can support a trustworthy theoretical minimum:

`TARGET -> SURVEY -> GROUND -> DEPEND -> COMPRESS -> EXAMINE -> FALSIFY -> SYNTHESIZE -> AUDIT -> STOP`

### 0. TARGET - pin the performance obligation

Write down internally:

- target capability and representative serious-work tasks
- intended learner and assumed entry knowledge
- expected level, context, and constraints
- intended use
- time sensitivity
- geographic/jurisdictional scope if relevant
- observable completion criteria
- exclusions
- likely source families

Do not yet write the artifact.

### 1. SURVEY - map before collecting

Build a provisional task-and-dependency map:

- **Target performances:** representative tasks the learner must complete
- **Problem families:** recurring forms of reasoning or practice within the target
- **Candidate dependencies:** concepts, methods, evidence standards, tools, and habits those tasks appear to require
- **Trailheads:** primary sources, standard problems, specifications, datasets, experiments, or cases that expose those dependencies
- **Boundaries:** adjacent material that may be valuable but is not yet shown necessary

Generate competing search paths. Do not commit to the first vocabulary you encounter.

For unfamiliar terminology, search before interpreting it.

### 2. GROUND - build a live source ledger

Search broadly, then promote only sources that deserve load-bearing use.

For each candidate source track internally:

- source ID: `S01`, `S02`, ...
- title
- author / institution
- date / edition
- source tier
- source type
- URL or durable identifier
- access result
- what claim(s) it directly supports
- important limitations

Prefer Tier 1–2 for the core. Use Tier 3 for pedagogy and Tier 4 for orientation only. Tier 5 is your own synthesis.

When a claim is current or likely to change, prefer current primary/official material and record access date.

A source discovered in search is **candidate evidence**. Open it before treating it as evidence.

### 3. DEPEND - recover the prerequisite structure

Work backward from target performances. Build an internal dependency graph whose nodes are candidate units and whose edges mean "requires for the target scope."

Identify:

- primitive objects and definitions
- invariants / conservation rules / contracts
- governing mechanisms
- impossibility or lower-bound results
- characteristic tradeoffs
- models of state, information, time, resources, uncertainty, composition, failure, and change where relevant
- standard problem forms
- empirical methods or evidentiary standards where the domain is empirical
- interfaces to adjacent fields
- hidden mathematical, technical, linguistic, or practical prerequisites

Separate true dependencies from conventional course order, fashionable vocabulary, and material that is merely helpful. Look for cycles, unsupported edges, and prerequisites assumed by every inspected source but named by none.

### 4. COMPRESS - find the smallest adequate set

Run repeated deletion passes over the candidate graph. For each unit apply:

- **Necessity:** What representative target performance becomes impossible, unreliable, or opaque without it?
- **Generativity:** Does it explain or enable several later results or problem families?
- **Non-redundancy:** Can retained units derive or cheaply replace it?
- **Prerequisite closure:** Would removing it leave another retained unit unusable?
- **Transfer:** Does it support unfamiliar cases rather than one memorized exercise?
- **Grounding:** Which inspected sources support the dependency or inclusion claim?

Remove units that fail. Add units only when a concrete capability failure or missing prerequisite requires them. Do not force a unit count.

For each unit answer:

- What must be understood?
- Why is it load-bearing?
- Which target performances and later units depend on it?
- What specifically fails if it is removed?
- Why can no retained unit subsume it?
- What closed-book problem or defense would reveal fake understanding?
- Which sources support its inclusion?

Record rejected and deferred candidates with a short reason. A comprehensive survey labeled "minimum" fails this stage.

### 5. SOURCE SPINE - curate for ownership, not collection

Build the smallest source spine that supports the retained units. It may include:

- foundational primary papers/texts
- authoritative textbooks/monographs/handbooks
- standards/specifications/datasets
- modern synthesis
- adjacent-field works that expose a deeper invariant

For each item record:

- role: spine / original / adjacent / reference / practicum
- which minimum unit it supports
- why it survives deletion from the source spine
- source tier
- verified official/free link when actually confirmed
- purchase/search link only if requested or useful, never as evidence

Do not call something “canonical” unless you have evidence for broad field status. Otherwise say “recommended,” “foundational,” “widely used in the sources inspected,” or another narrower claim.

### 6. EXAMINE - make ownership behaviorally testable

Build a compact examination that tests the retained units under declared resource constraints.

Include:

- at least one blank-page regeneration task for each unit, combining units where appropriate;
- at least 3 unseen or transfer problems;
- at least 2 oral-defense prompts;
- 1 integrated challenge spanning several units;
- a process rubric shared across the tasks.

The process rubric must inspect:

- assumptions and framing;
- representation choice;
- decomposition and intermediate derivation;
- checks against invariants, evidence, units, or counterexamples;
- recovery from an unproductive route;
- boundary conditions and uncertainty;
- clarity under questioning.

Do not provide full solutions unless requested in the original command. When solutions are requested, place them inside the same artifact after the examination. Otherwise provide a graduated hint ladder only: orienting question, relevant principle, then partial structure. Productive struggle must be time-boxed and diagnostic; never treat suffering, speed, or conformity as evidence of mastery.

An unconventional route passes when it is sound. Grade the process before the answer.

### 7. FALSIFY - attack the minimum before publishing it

For each major synthesis claim ask:

- What is the strongest alternative organization of the field?
- What important tradition/source would disagree?
- Which retained unit has the weakest removal case?
- Which omitted unit would a credible practitioner insist is prerequisite?
- Which analogy breaks?
- What boundary condition invalidates the claim?
- Is a supposed invariant actually contingent technology or fashion?
- Did the search overrepresent one school, language, geography, vendor, or era?

Actively search for at least one credible counter-source when the topic is contested or the synthesis is unusually strong.

If the claim survives, say so. Do not invent a weakness to fill a template.

### 8. SYNTHESIZE - write exactly one artifact

Before writing, read `references/artifact-contract.md` and follow it exactly enough that another agent can audit the file without this conversation.

Every load-bearing factual paragraph should contain one or more source IDs like `[S03]` that resolve in the artifact's Source Registry.

Use explicit markers for non-source-backed reasoning:

- `[SYNTHESIS]` — your integration across grounded material
- `[INFERENCE]` — conclusion inferred from cited evidence but not directly stated by a source
- `[UNKNOWN]` — unresolved or inaccessible
- `[CONTESTED]` — credible sources disagree

Markers do not excuse careless reasoning. They prevent synthesis from masquerading as source fact.

### 9. AUDIT - attack the artifact itself

Before finishing, perform these checks:

**Provenance**
- Every `[Sxx]` resolves to one Source Registry entry.
- Every load-bearing factual claim has direct support.
- No citation depends only on a search snippet when the source was reachable.
- Quotes, page numbers, and exact statistics appear only when actually verified.

**Source quality**
- The theoretical minimum is anchored mostly in Tier 1–2 evidence.
- Tier 4–5 material does not carry the core.
- Current claims use current sources.
- Contested claims show meaningful opposing evidence.

**Reasoning**
- Definitions precede conclusions.
- Assumptions are visible.
- Strong conclusions have matching evidence strength.
- Analogies name what transfers and what does not.
- “Canonical,” “consensus,” “proven,” “safe,” and “verified” are not used casually.

**Coverage**
- The target capability, entry assumptions, and scope are explicit.
- Every retained unit names dependencies, removal failure, source support, and a regeneration test.
- Rejected and deferred candidates make the compression boundary visible.
- The artifact includes the dependency map, theoretical minimum, source spine, examination, process rubric, uncertainty/contradiction ledger, claims/evidence ledger, and source registry.
- It names what was not searched or could not be verified.

**Mastery design**
- Closed-book tasks require reconstruction rather than terminology recall.
- Unseen problems test transfer.
- Oral defenses require ownership of assumptions, errors, and limitations.
- The process rubric can pass a sound unconventional route and reject an unsupported correct answer.
- Hints and solutions do not erase the initial attempt.

**Hallucination traps**
- Search every source title/author pair in the artifact against the live source ledger.
- Search every URL in the artifact against opened/verified URLs.
- Remove attractive but unverified references.
- If a source's existence was found but content was not inspected, mark verification as `existence-only` and do not cite it for a substantive content claim.

If `python3` is available and the client exposes bundled skill resources, run `scripts/theoretical_minimum_lint.py <artifact-path>` from this skill directory without producing another file. In Claude Code, `${CLAUDE_SKILL_DIR}/scripts/theoretical_minimum_lint.py` is the resolvable path. If the client cannot resolve bundled scripts, perform the same audit manually rather than guessing a path.

Fix structural errors. Treat warnings as prompts for human judgment. The linter never certifies factual correctness.

### 10. STOP - return only the artifact

Stop when:

- repeated deletion passes no longer remove a unit without breaking a named target performance or prerequisite edge;
- new high-quality sources mostly refine rather than reorganize the minimum;
- load-bearing claims are grounded at the appropriate tier;
- credible disagreements are represented;
- the examination can distinguish answer recall from regeneration, process quality, transfer, and defense;
- remaining gaps are explicit.

Do not keep browsing to maximize source count.

After writing the file, return only:

`Created: <artifact-path>`

plus one short clause if the artifact is explicitly `limited` because source access was blocked.
